// design language · for the apps we build

app design language

One dark console language for every product we ship — kuita (voice & IVR), daraja (WhatsApp identity & SSO) and the aml compliance console. Every token, component and pattern on this page is lifted 1:1 from the signed-off mockups: same paper, same accent, same two fonts. Nothing here is invented — and nothing should be invented outside it.

this language is deliberately separate from the ijaio brand guide — different world, different rules. the ijaio guide covers the consumer brand; this covers the tools we build.

01principles

how we design

Eight principles govern every screen. Most of them are written verbatim in the mockups themselves — they are rules we already follow, now collected in one place.

dark, and only dark

data-theme=dark

Every app ships dark. There is no light theme, and no half-themes. The paper stack is warm-black, not pure black — text sits on #0b0b0d–#1c1c21, never #000.

same paper, same accent, same two fonts

nothing invented

The shared tokens are non-negotiable. New screens are assembled from existing pieces — a new app means new content, never a new look.

the left menu never scrolls

100dvh · overflow:hidden

The sidebar is a fixed 100dvh column with overflow:hidden. If navigation doesn't fit, restructure the menu — never add a scrollbar. Module switchers keep item counts low.

status is monochrome

red = failure only

Status pills are outline style in one ink. Colour is information, not decoration: red is reserved for genuine failure. No colour-coded stage ladders.

machine voice is mono

jetbrains mono

Anything the system says — labels, nav, keys, counts, states, endpoints — is set in JetBrains Mono, uppercase, tracked. Anything a human says — page titles, body, product copy — is Geist.

data dense, chrome quiet

hairline rules

Panels are flat, separated by 1px rules that barely exist (#16161a–#2a2a30). No drop shadows inside the app — the only shadow in the language is on the login glass card. Space belongs to data.

one view, no scroll

login only

The login is a single centred view that fits the viewport — 100dvh, overflow:hidden. No scrolling to reach a button, ever.

the print is at the door

african print

The only imagery in the products is the recreated African print behind the login glass card. Inside the app: no photography, no illustration — data only.

03typography

geist + jetbrains mono

Two families, strict roles. Geist (300–700) is the human voice — titles, body, values. JetBrains Mono (400–600) is the machine voice — labels, nav, data, states. If a text is monospace, the system is speaking.

always

  • tabular numerals for every count, price and time
  • uppercase + tracking for anything mono-labelled
  • titles in sentence case — voice traffic not Voice Traffic
  • lowercase microcopy — “paste your key here”, “checking api…”

never

  • a third typeface, or system serifs
  • mono for long body copy — it is a label voice
  • centre-aligned data tables
  • pure white #fff or pure black #000 anywhere

04app shell

two shells, one anatomy

Two shells exist. The sidebar console (kuita, aml) is for multi-page products. The single-column console (daraja) is for focused tools. Pick by navigation weight, not by taste.

shell A — sidebar console

multi-page

Grid 232px 1fr, max-width 1320px, centred. The sidebar is fixed at 100dvh with overflow hidden — it never scrolls. Only the main column scrolls, under a sticky topbar of breadcrumbs.

shell B — single-column console (daraja)

No sidebar, no boxed containers. A top nav (brand left, ● online status right), then one centred column. Radius opens up to 14px / 10px — the softest corner in the language.

06status & feedback

monochrome first

The rule, verbatim from the merged console: status is monochrome — outline pills, one ink colour; red is reserved for genuine failure; no colour-coded stage ladders. Colour is spent, not sprinkled.

situationuseexample
any neutral stagedefault ink pillpending
system alive / connectedgreen dot + “online”● online
live activitycyan — dot, eq, “live” taglive
needs attentionamber text or pillretrying
genuine failurered — the only red on screenfailed

a screen carrying two reds has already broken the rule. if everything is urgent, nothing is.

07login standard

the door · shared by all apps

Every app opens the same way: one centred glass card on a recreated African print, in a single non-scrolling view. The print is the only place the products show imagery — it is the door, and the door is warm.

08voice

how the products speak

lowercase microcopy

Hints and machine chatter are lowercase, terminal-style: paste your key here checking api… no results yet

// eyebrows

Daraja's signature: eyebrows may lead with a comment slash — // secure console // daraja · identity · sso. The system narrating itself.

arrows & dots

Primary actions end with →; living states lead with ●. Two glyphs that carry meaning — never use them decoratively.

10the rules

pre-ship checklist
  • 01dark only — paper stack #0b0b0d–#1c1c21, warm ink #f2f1ec, never #000/#fff.
  • 02tokens lifted 1:1 — same paper, same accent, same two fonts. no new colours, no new faces.
  • 03the sidebar never scrolls — 100dvh, overflow hidden; restructure before you scroll.
  • 04status is monochrome — outline pills, one ink; red reserved for genuine failure; no stage ladders.
  • 05mono is the machine voice — labels, nav, keys, states; geist is the human voice — titles and body.
  • 06tabular numbers wherever digits can change.
  • 07buttons are outlines — accent border means primary; arrows end actions; no filled blocks.
  • 08one shadow in the language — the login glass card. nowhere else.
  • 09the login standard — one glass card, one print, one view, no scroll, no sign-up.
  • 10imagery stays at the door — inside the app, data only.
