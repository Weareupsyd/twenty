# Protecta Bode - Reports Suite

Answers the three questions leadership asked for: **What is each agent earning? How is each agent performing? Who is pushing the product for which broker?** Plus the standard insurance ops pack. All reports read the same Postgres the portals write to (bot, web, partner API included), so numbers always reconcile. Inherited from AgriLink: the `reports` API module + audit log; extended here for insurance.

**Definitions used everywhere:**
- **GWP** - gross written premium (confirmed payments only; pending payments excluded).
- **Attribution** - a policy belongs to the partner on `quotes.created_by` (agent) and that agent's parent `broker_id` (broker). WhatsApp/web self-service = *direct*; partner API = the calling partner.
- **Commission status machine** - `accrued` (payment confirmed) -> `payable` (after 14-day cooling period, month-end cut) -> `paid` (payout run) / `clawed_back` (policy cancelled in cooling window).
- **Active agent** - ≥1 converting quote in the last 30 days.

## 1. Agent commission statements (monthly, per agent)

One per agent per month; rendered as PDF (email template `commission-statement.html` attaches it) and in the agent portal.

| Section | Fields |
|---|---|
| Header | Agent name/code, parent broker (if any), statement month, status (payable/paid) |
| Summary | Policies sold, premium written (UGX), commission earned, adjustments, **net payable** |
| Breakdown | New business vs renewals; by product (Bode-01 …); clawbacks listed line-by-line with policy refs |
| Ledger | Per policy: date, policy no, plate, premium, rate (e.g. 10%), commission, status |
| Footer | Payout date, bank account last-4, "raise discrepancies within 7 days" |

Generated by the month-end job (1st, 06:00 EAT) -> PDF to documents store -> email to agent (and parent broker, CC'd) -> status flips `payable`. Payout run marks `paid` with `payout_ref`.

## 2. Agent performance report (admin + broker-portal view of own agents)

| Metric | Why it matters |
|---|---|
| Quotes created (30d) | Activity |
| Quote -> policy conversion % | Closing quality |
| Policies sold / GWP / avg premium | Volume & value |
| Retention % (renewals of own book) | Customer care |
| Time-to-close (quote -> payment, median) | Sales velocity |
| Claims ratio on agent's book (claims cost / premium) | Sales-quality early warning |
| Active days (days with ≥1 quote) | Consistency |
| Rank vs peers (percentile badge) | Motivation / league table |

Views: agent detail page (trend chart + client list), agency/team rollup, and a **leaderboard** (top 20 by GWP & by conversion) for sales incentives. Broker portal sees the same table restricted to its agents.

## 3. Agents-brokers report (distribution tree)

- **Tree view:** Broker -> its agents -> each agent's numbers (policies, GWP, commission), with sub-totals per broker and grand total.
- **Attribution mix per broker:** direct vs WhatsApp vs partner-API sales their agents push.
- **Orphan watch:** agents with no parent broker, brokers with <2 active agents 60 days after onboarding.
- **Broker scorecard:** GWP trend, agent activation rate (signed -> first sale), retention, commission cost as % of GWP.
- Export: CSV/XLSX; IRA-facing distribution summary (premium & commission by channel) generated quarterly.

## 4. Standard ops pack (admin)

| Report | Content | Cadence |
|---|---|---|
| Daily flash | New quotes, conversions, GWP, payment failures, top channels | Daily 07:00 email |
| Reconciliation | MoMo/Airtel/bank settlements vs policies; unmatched items queue | Daily + on demand |
| Renewals due | 30/14/3/0-day buckets, by owner (customer direct / agent / broker) | Weekly |
| Claims | FNOL count, status aging, ratio by vehicle age & channel | Weekly |
| Product funnel | Calculator starts -> quotes -> payments -> issued, per channel | Weekly |
| Partner API usage | Volumes, error rates, top endpoints per partner | Weekly |
| IRA returns pack | Premium by class, claims by status, distribution & commission summary, KYC stats | Quarterly |
| Audit extract | All privileged actions in period | On demand |

## 5. Implementation notes

- All heavy queries as SQL views (`v_agent_monthly`, `v_broker_tree`, `v_daily_flash`) + materialized views refreshed 06:00 EAT for the big ones; API endpoints page + filter (`?from&to&broker_id&channel`).
- Every report downloadable as CSV/XLSX/PDF; scheduled ones delivered by the email service using the existing templates.
- Broker-portal and partner-API reports are **row-scoped by partner id at the query level** (never by hiding UI).
- Reconciliation report is the cash-truth source: if it disagrees with the commissions ledger, the ledger is wrong - alert, don't guess.
